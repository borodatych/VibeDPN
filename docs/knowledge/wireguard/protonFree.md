# Proton VPN Free как выход по файлу: что дал замер на коробке

Снято 2026-09-16 на коробке `home` (Debian 13, Ростелеком AS12389, Карачаево-Черкесия,
двойной NAT: 192.168.1.1 → 192.168.0.1 → 109.172.26.177).

## Что даёт бесплатный тариф (по страницам Proton)

- Файлы WireGuard генерируются и на бесплатном тарифе: `account.protonvpn.com` → Downloads →
  WireGuard configuration; из опций доступен только VPN Accelerator, сервер — из списка
  «Free server configs» или рекомендованный.
  Источник: https://protonvpn.com/support/wireguard-configurations
- Роутер разрешён на всех тарифах и считается одним соединением, сколько бы устройств за ним ни было.
  Источник: https://protonvpn.com/support/installing-protonvpn-on-a-router
- Ограничения: одно соединение на аккаунт, «Medium VPN speed», в приложении сервер назначается
  случайно, P2P и стриминг — только платно. Источник: https://protonvpn.com/pricing
- Бесплатные страны на 16.09.2026: Канада, Япония, Мексика (физически в США, «Smart Routing»),
  Нидерланды, Норвегия, Польша (один сервер), Румыния, Сингапур, Швейцария, США.
  Нагрузка серверов видна в списке; Польша и часть США были на 100 %.
- Срок файла — год (в панели «expires Sep 16, 2027»), продлевается кнопкой Extend.
  Закрытый ключ Proton не хранит: не скачал сразу — создавать заново.

## Формат файла

Две секции. `[Interface]`: `PrivateKey`, `Address = 10.2.0.2/32` (у части серверов ещё
`2a07:b944::2:2/128`), `DNS = 10.2.0.1` (и IPv6 у тех же). `[Peer]`: `PublicKey`,
`AllowedIPs = 0.0.0.0/0, ::/0`, `Endpoint = <IPv4>:51820`. Комментариями — имя ключа,
`Bouncing`, состояние NAT-PMP и Accelerator. `PersistentKeepalive` нет — entrypoint шлюза
добавляет свой. Все девять файлов прошли `read_peer_config` без замечаний; IPv6-адрес и
`::/0` шлюз пропускает с записью в лог («the tunnel is IPv4 for now»).

## Одно соединение на аккаунт — значит один включённый выход

Каждый включённый `wg-<имя>` держит собственную сессию WireGuard. Два файла одного бесплатного
аккаунта, включённые одновременно, выбивают друг друга. Файлы остальных стран лежат на коробке
в `secrets/proton/` (root, 600) и подключаются `vibedpn uplink add` по одному.

## Рукопожатие с серверами Proton через Ростелеком не проходит

Замер после `vibedpn up` с `wg-proton-nl` (NL-FREE#124, 185.107.56.44):

- `wg show wg0 transfer`: tx 1776, rx 0; `latest-handshakes` — 0.
- `tcpdump -ni enp1s0 udp port 51820` на WAN коробки: инициации по 148 байт уходят каждые ~5 с,
  ответных пакетов нет.
- Смена `Endpoint` на порты 88, 1224, 4500, 443, 53, 500, 1194, 5060 внутри контейнера
  (`wg set wg0 peer … endpoint`) — рукопожатия нет ни на одном (Proton заявляет для WireGuard
  только 51820, остальные пробовались на всякий случай).
- Те же адреса всех девяти серверов отвечают на ICMP (84–320 мс) и держат TCP 443 (кроме RO);
  UDP как таковой работает — DNS-запрос к 1.1.1.1 по UDP отвечает.
- Traceroute глохнет после третьего хопа (Ростелеком не отдаёт TTL-exceeded дальше).

Вывод по замеру: режется именно WireGuard к адресам Proton, а не адреса и не UDP.
Для сети Mysterium раньше измерено обратное — туннели WireGuard к нодам проходят
(`docs/decisions.md`, решение 22): блокировка привязана к адресам VPN-поставщика.

Тот же результат с телефона (Android, приложение WireGuard, конфиг CH-FREE#10 по QR-коду
из `segno`): за 77 с 16 инициаций «Handshake did not complete after 5 seconds, retrying»,
ответа нет. Телефон шёл через мобильную сеть Т-Мобайл с выключенным Wi-Fi (слова владельца):
два разных оператора дают один результат, значит блокировка не у Ростелекома, а общая.

**Не разделено до конца:** «российские операторы режут WireGuard к Proton» и «ключ не активен
у Proton». Разделяет только рукопожатие из-за границы; зарубежной машины у проекта нет, а
инициация с незарегистрированным ключом ничего не даст — WireGuard молчит чужим пирам.
Против «ключ не активен»: два разных свежих конфига, оба показаны в панели Proton активными,
страница поддержки подтверждает файлы на бесплатном тарифе.

## Что показала проверка про сам продукт

- `vibedpn doctor --network` проверял адрес выхода только у `vps` и `dpn` (`_exits` в
  `doctor.py`); выходы `wg-<имя>` не проверялись — отсутствие рукопожатия доктор не видел.
  Исправлено в тот же день: каждый включённый выход опрашивается, `[FAIL] exit wg-<имя>`.
- Под `sudo vibedpn doctor` строка `secrets` давала WARN «cannot check wg-proton-nl.conf
  (secrets/ is root-only)»: сборщик фактов статил только файлы, известные `init`, а не
  `required_secrets(config)`. Исправлено вместе с предыдущим.
- `docker compose ps wg-proton-nl` отвечает «no such service»: сервис объявлен в
  `compose.wg.yaml`, который ядро подключает само (`compose_argv`); `exec` при этом работает.
  `vibedpn status` показывает контейнер верно.
- Яндекс.Браузер сохраняет загрузки в папку последнего сохранения — при работе через расширение
  файл с ключом упал в чужой репозиторий (`VibeDub/misc/`). Скачанные файлы переносить сразу
  в `secrets/` (в `.gitignore`), проверять `git status`.
