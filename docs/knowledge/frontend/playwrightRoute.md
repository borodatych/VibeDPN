# Playwright: `context.route` с функцией вешает страницы

**Контекст:** e2e панели `ui/` на Bun и Playwright 1.62.1, задание CI `ui-e2e`; найдено 2026-10-02.

## [грабли] Функция-предикат перехватывает каждый запрос страницы

Страж запросов наружу (`panelContext` в `ui/src/test/lib/e2e.ts`) был задан функцией: `context.route((url) => …, handler)`.
В CI страницы после нескольких тестов переставали переходить по адресам: `goto` ждал `load` 30 с, сервер панели не получал ни одного запроса, а `page.close()` тоже не завершался.
Локально прогоны проходили.

Причина — в том, как Playwright передаёт шаблон драйверу (`serializeURLMatch` в `playwright-core/lib/coreBundle.js`).
Строку, RegExp и URLPattern драйвер сверяет сам и перехватывает только совпавшие запросы.
Для функции шаблона нет, поэтому драйвер перехватывает каждый запрос страницы — чанки, шрифты, запросы данных — и по каждому ждёт решения процесса тестов.
Когда процесс тестов отвечает с задержкой, запросы вкладки встают.

**Решение:** страж — RegExp с отрицательной проверкой: всё, что не `localhost`, `127.0.0.1` и `[::1]` по схемам `http`, `https`, `ws`, `wss`.
Адреса `data:` Playwright не перехватывает вовсе.

**Проверено:** после замены задание `ui-e2e` зелёное (CI на `7b35787`); подмена — ссылка на Google в `<Head>` — роняет smoke-тест «the panel loads nothing from outside the box».
Связь «функция → зависание» выведена из исходника и исхода CI, отдельным опытом не воспроизведена.

## [грабли] Лишний процесс на порту поддельного ядра

E2E поднимают поддельное ядро на `CORE_API_PORT`.
Если на этом порту уже работает другое поддельное ядро, новое не стартует, и тесты молча идут против чужого со старыми данными: 11 ложных падений.
Перед прогоном: `pgrep -fl tests.panel_core` — пусто.
