# Выход smart-режима закрепляется за соединением

Найдено 2026-10-31 на коробке `home`: Playdate качал прошивку с S3 через правило `via: tor`.

## Почему соединение рвалось

Наборы `smart_*` заполняет резолвер ядра из ответов DNS, элемент живёт TTL ответа плюс 60 секунд.
S3 отдаёт адрес с TTL 5 секунд, значит адрес держится в наборе около 65 секунд.
Метка выхода ставилась на каждый пакет по наборам, без памяти о соединении.
Скачивание дольше минуты: адрес выпадал из набора, остаток потока уходил напрямую, а соединение Tor
напрямую не продолжить — поток вставал.

## Что сделано

Выбор пишется в `ct mark` установленного соединения с битом `0x80000000` (`STEERED_CT_BIT`),
прямой путь тоже: у него метка 0, поэтому без бита «выбор сделан» его не отличить от «не выбирали».
Пакет установленного соединения получает метку из `ct mark` без бита и не проходит `steer`.
Политики устройств стоят выше и проверяются на каждом пакете: блокировка действует сразу.

## Ложное «learned» перебивало правило

Механизм learned по времени записал `memfault-…s3.amazonaws.com` спутником `play.date` (direct):
устройство спросило его сразу после `play.date`.
`reload` клал выученное в индекс поверх правил из конфига, и явное `via: tor` проигрывало.
`vibedpn rule forget` убирал имя из индекса целиком, вместе с явным правилом, до перезапуска ядра.
Теперь `RuleIndex` помнит явные имена, выученное и цели CNAME их не трогают.

Источники: `core/vibedpn/templates/lan-router.nft.j2`, `core/vibedpn/engine/resolver.py`;
`ct mark` и `meta mark` — https://wiki.nftables.org/wiki-nftables/index.php/Setting_packet_metainformation
