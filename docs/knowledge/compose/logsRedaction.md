# Журналы служб для панели: флаги Compose и вычистка секретов

## Флаги `docker compose logs`

Источник: https://docs.docker.com/reference/cli/docker/compose/logs/

- `--no-log-prefix` — без префикса `служба-1  |` в каждой строке: в панели служба и так названа
- `--no-color` — без ANSI-цветов: в `<pre>` они видны мусором
- `-n, --tail` — строк с конца **для каждого контейнера** (по умолчанию `all`)
- `-f, --follow` — поток, пока процесс не остановят

Вывод читается построчно с объединёнными stdout и stderr (`compose.stream`): так и поток `-f` чистится строка за строкой, и ни одна строка не уходит мимо вычистки.

## Что пишут службы коробки

- xray (сервер доступа, выход по ссылке) — UUID людей, ссылки `vless://` при отладке, ключи REALITY
- ядро и бот — адрес Bot API `https://api.telegram.org/bot<id>:<токен>/…` в ошибках httpx
- DDNS — адрес обновления с `token=` в запросе
- WireGuard — открытые ключи пиров (не секрет сами по себе, но имя пира по ним находится)
- hostapd — `wpa_passphrase=` при отладке конфига

## Как ловить

Образцами, а не разбором формата каждой службы — форматы меняются от версии к версии.
Порядок важен: сначала ссылка и пароль в URL, потом голые ключи внутри них.

- Токен Telegram: перед цифрами нет границы слова в `bot123…`, поэтому `(?<![0-9])\d{6,12}:…`, а не `\b`
- `wpa_passphrase=`: `_` — символ слова, `\bpassphrase` его не видит; ключ ловится как `\w*(passphrase|token|key|…)=`
- Ключ WireGuard — base64 от 32 байт: 43 символа и `=`, причём 43-й символ из `AEIMQUYcgkosw048` (четыре младших бита пустые)
- Ключ REALITY — base64url от 32 байт без `=`: 43 символа с той же последней буквой; так короткий хеш коммита или id контейнера (hex) не попадает под замену

Тесты на каждый образец — `core/tests/test_logs.py`.
