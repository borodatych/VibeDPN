# Запись файла, смонтированного в контейнер

## [провайдер] Атомарная замена поверх файлового bind-mount невозможна

**Контекст:** `vibedpn device set` и `PUT /devices` (Stage 5, 2026-09-13) — ядро правит `config.yaml`.
**Суть:** атомарная запись — временный файл рядом и `rename` поверх цели. Когда цель смонтирована в
контейнер отдельным файлом (`-v ./config.yaml:/etc/vibedpn/config.yaml`), она — точка монтирования, и
`os.replace` внутри контейнера падает с `[Errno 16] Device or resource busy`; файл на хосте не меняется
(проверено исполнением на Docker 29.5.2). Запись на месте (truncate + write) прошла бы, но оборванная
посередине оставила бы битый конфиг. Решение — монтировать **каталог**: `.:/etc/vibedpn/box`, тогда
`rename` внутри каталога атомарен. Грабля второго шага: временный файл создаётся `mkstemp` с правами
600 от root, и после `rename` так выглядит уже сам `config.yaml` — владелец теряет доступ к своему
файлу. Поэтому запись идёт через `atomic.write_like`, который выставляет временному файлу права и
владельца заменяемого (`fchmod` + `fchown` под root). Отсутствующий `config.yaml` при монтировании
каталога по-прежнему останавливает ядро одной строкой — его читает `load_config`.
**Источники:** https://docs.docker.com/engine/storage/bind-mounts/ , `core/vibedpn/atomic.py`.

## [опыт] Файл, заменённый на хосте через rename, до контейнера не доходит

**Контекст:** файлы выходов WireGuard (`secrets/wg-<имя>.conf`, `secrets/wg-client.conf`) смонтированы в шлюзы по одному, а пишутся атомарно: временный файл и `rename` поверх (2026-09-23).
**Замер** на Linux внутри VM colima (ядро 6.8, Docker 29.5.2), файл на диске VM: контейнер с `-v f.conf:/etc/wg0.conf`, на хосте `mv f.new f.conf` — внутри по-прежнему старое содержимое; следующая запись на месте в новый файл тоже не видна.
Монтирование держит тот файл, что был на месте при старте контейнера, и наблюдатель образа `wg`, сравнивающий отпечаток файла, подмены не заметит.
На пути, общем с macOS (virtiofs colima), симптом другой: после `rename` файл внутри пропадает вовсе.
**Как применять:** шлюзу с одиночным файлом — отпечаток содержимого в окружении (`compose.file_digests`), чтобы `vibedpn up` пересоздал контейнер; то, что переписывается часто, монтировать каталогом, как `data/xray/config` и `data/tor/config`.
**Источники:** https://github.com/moby/moby/issues/15793 («File mount does not update with changes from host»).
