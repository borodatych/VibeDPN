# Адрес обновления DDNS: как сервисы отвечают и как часто их звать

**Контекст:** `ddns` коробки (решение 30, `engine/ddns.py`), 2026-09-23.
Имя из ссылок сервера доступа должно следовать за меняющимся домашним адресом; ядро само зовёт адрес обновления сервиса.

## [опыт] «Нет» приходит и с кодом 200

Сервисы говорят об отказе своими словами, и код HTTP это не всегда отражает:
- **DuckDNS:** хороший ответ `OK`, плохой `KO` (спецификация); запрос с чужим токеном 23.09.2026 получил `KO` с HTTP 200;
- **протокол dyndns2 (No-IP, Dyn):** отказ — слово в теле ответа: `nohost`, `badauth`, `badagent`, `!donator`, `abuse`, `911` у обоих, у Dyn ещё `notfqdn`, `numhost`, `dnserr`; успех — `good <адрес>` или `nochg <адрес>`;
- **dynv6:** неверный токен — `invalid authentication token` с HTTP 401 (запрос 23.09.2026); текст успешного ответа на странице API не описан.

**Как применять:** вызов удался, только если код 2xx и первое слово ответа не из слов отказа; первое слово сравнивается без учёта регистра.

## [опыт] Слепой вызов раз в пять минут — повод заблокировать клиента

No-IP пишет прямо: *«Excessive nochg responses may result in your client being blocked»*.
`nochg` по той же странице — «IP address is current, no update performed», то есть ровно то, что даёт вызов по таймеру.
**Как применять:** ядро узнаёт внешний адрес само (раз в пять минут) и зовёт сервис только при его смене — и раз в сутки на случай, если сервис потерял запись: это наша страховка, а не требование какого-то сервиса.

## [опыт] Внешний адрес — у ipify, который не пишет журналов

`https://api.ipify.org` отвечает адресом вызывающего одной строкой; на странице сервиса: *«No visitor information is ever logged»*.
Тот же сервис спрашивает `vibedpn doctor --network`, поэтому адрес в `ddns` и в `doctor` один и тот же.

## [договорённость] Адрес обновления — секрет

Токен едет в самом URL, поэтому адрес обновления хранится в `secrets/ddns-url` (600), принимается только `https://`, не печатается и не возвращается API: наружу уходит лишь имя хоста сервиса, а в сообщениях об ошибке — хост и класс ошибки.
Сервису, который хочет адрес в самой ссылке, на его место ставится `{ip}`.

**Источники:** https://www.duckdns.org/spec.jsp (`OK`/`KO`); https://www.noip.com/integrate/response (ответы dyndns2 у No-IP, предупреждение про `nochg`); https://help.dyn.com/remote-access-api/return-codes/ (коды Dyn, включая `notfqdn`, `numhost`, `dnserr`); https://dynv6.com/docs/apis (API dynv6); https://www.ipify.org/ (журналы не ведутся).
