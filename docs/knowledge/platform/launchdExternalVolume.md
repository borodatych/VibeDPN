# Фоновому заданию macOS внешний том недоступен целиком

Измерено 2026-09-20 на Mac владельца при заведении еженедельной копии коробки.

## Что происходит

LaunchAgent пользователя (`~/Library/LaunchAgents/*.plist`, загруженный `launchctl bootstrap
gui/<uid>`) не может на внешнем томе **ничего**: ни читать, ни писать, ни запускать. Пробное
задание с тремя действиями подряд:

```
--- read:   ls: /Volumes/Storage/…: Operation not permitted
--- write:  touch: /Volumes/Storage/…: Operation not permitted
--- exec:   /Volumes/Storage/…/script.sh: Operation not permitted
```

Та же команда, запущенная в терминале от того же пользователя, работает: у терминала разрешение
есть, у фонового задания — нет. Это TCC, и молча: диалога «разрешить доступ к съёмному тому»
фоновому процессу никто не покажет.

## Как это выглядит, если не знать

Первая попытка: задание падает с `last exit code = 78 (EX_CONFIG)` и **без единой строки в
журнале** — потому что журнал тоже лежал на внешнем томе, и launchd не смог его открыть. Пока
журнал не переехал в домашний каталог, причина не видна вообще.

Вывод для любых заданий: **путь журнала выбирать первым и в домашнем каталоге**, иначе отказ
окажется немым.

## Вторая мина: личный `~/.ssh/config` со ссылкой наружу

После переезда журнала задание сказало:

```
/Users/…/.ssh/config line 1: Can't open user config file /Users/…/.colima/ssh_config: Operation not permitted
/Users/…/.ssh/config: terminating, 1 bad configuration options
```

`~/.colima` — симлинк на внешний том (кэши там живут по правилу владельца), colima дописала в
`~/.ssh/config` строку `Include`. Недоступный включаемый файл — **фатальная** ошибка ssh: он не
просто пропускает строку, он отказывается стартовать. Любое фоновое задание, зовущее ssh, умирает
до первой команды.

Лечение: не пользоваться личным конфигом. `scripts/installBackupTimer.sh` вырезает блок
`Host <алиас>` из `~/.ssh/config` в свой файл рядом с заданием (права 600), а `pullBackup.sh`
принимает его через `VIBEDPN_SSH_CONFIG` и зовёт `ssh -F`.

## Решение целиком

Задание живёт в домашнем каталоге: копия скрипта в `~/Library/Application Support/vibedpn/`, свой
ssh-конфиг рядом, архивы в `~/VibeDPN-backups`, журнал в `~/Library/Logs/`. Внешний том не
упоминается нигде.

Альтернатива — выдать Full Disk Access тому бинарю, который запускает задание (`/bin/zsh`), руками
в системных настройках. Не выбрана: разрешение на весь shell шире задачи, и его нельзя поставить
из кода — это клик владельца.

Цена принятого решения: архивы занимают место на системном диске (одна копия коробки ≈ 36 МБ,
четырнадцать ≈ 500 МБ при 88 ГБ свободных — проверено перед выбором).
