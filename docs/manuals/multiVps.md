# НЕСКОЛЬКО VPS И ЗАПАСНЫЕ ВЫХОДЫ

Как подключить к домашней коробке второй VPS и сделать так, чтобы трафик сам уходил на него, когда
первый замолчал, и сам возвращался, когда тот ожил.
Формат ключа — в [configSpec.md](configSpec.md), раздел `routing`, ключ `fallback`; почему так
устроено — решение 32 в [decisions.md](../decisions.md).

---

## 1. Как это работает

У каждого выхода коробки свой контейнер-шлюз и своя таблица маршрутизации.
Ядро раз в 5 секунд спрашивает каждый шлюз, отвечает ли он.

Пока шлюз выхода отвечает, трафик этого выхода идёт через него.
Замолчал — таблица выхода переключается на шлюз первого отвечающего выхода из `routing.fallback`.
Ожил свой шлюз — трафик возвращается к нему; ожил выход повыше в цепочке — трафик переходит на него.
Не отвечает никто — решает `routing.failopen`: `false` держит трафик (kill-switch), `true` пускает напрямую.

Цепочка действует на любой выход, через который идёт трафик LAN:
- Выход режима `full`
- Выходы правил умного режима
- Выходы политик устройств

Переключение — один шаг маршрута: окна, в котором трафик шёл бы мимо выходов, нет.
Соединения, открытые через молчащий выход, рвутся — браузер и приложения открывают новые сами.

Второй VPS для коробки — обычный свой выход WireGuard `wg-<имя>`, как Proton или Mullvad.
Тот же приём годится для любого запасного: `tor`, `xray`, `dpn`, свой выход у платного поставщика.

## 2. Подключить второй VPS

Всё делается в панелях двух коробок, без SSH и команд.
Панель VPS открывается только через его туннель: включите её в `config.yaml` VPS (раздел `ui`, `enabled: true`) один раз при установке.

**Шаг 1.** В панели второго VPS откройте страницу «Пиры».
В блоке «Добавить пира» введите имя, например `home`, и нажмите «Добавить».
Переключатель «Только панель ноды через туннель» не трогайте: он для ноутбука или телефона, а не для домашней коробки.

**Шаг 2.** Появится карточка «Файл home» с QR-кодом.
Нажмите «Скачать home.conf»: браузер сохранит файл.
Потерялся — кнопка «Файл» в строке пира выдаст его снова.

**Шаг 3.** В панели домашней коробки откройте «Выходы» → «Добавить выход».
Выберите скачанный файл, имя выхода — например `second`, и нажмите «Добавить выход».
Коробка сама проверит файл и поднимет выход `wg-second`; строка состояния на странице скажет, когда он применён.

**Шаг 4.** Удалите скачанный файл с компьютера: в нём закрытый ключ.

**Проверка:** на странице «Пиры» второго VPS у пира `home` связь «на связи», на «Статусе» домашней коробки у выхода `WG-SECOND` шлюз «отвечает».

**То же командами.** На VPS:

```bash
sudo vibedpn peer add home --out home.conf
```

На домашней коробке, после переноса файла:

```bash
sudo vibedpn uplink add second /tmp/second.conf
sudo vibedpn up
rm /tmp/second.conf
```

## 3. Собрать цепочку

**Панель.** Страница «Статус», карточка «Маршрутизация», блок «Запасные выходы».
Кнопками внизу выход добавляется в конец цепочки, стрелкой поднимается выше, крестиком убирается.

**CLI.** Выходы — по порядку, первым тот, что предпочтительнее:

```bash
sudo vibedpn fallback wg-second tor
```

Применяется сразу, без перезапуска.
Посмотреть цепочку — `vibedpn fallback` без аргументов; убрать — `vibedpn fallback --clear`.

**Руками.** В `config.yaml`, в разделе `routing`, затем `sudo vibedpn up`:

```yaml
routing:
  mode: full
  default_upstream: vps
  failopen: false
  fallback: [wg-second, tor]
```

Каждый выход цепочки должен быть включён в `upstreams`.
Страны `dpn-<код>` в цепочку не берутся: они обслуживают только свои правила.

---

## 4. Проверить

Остановите шлюз первого VPS и посмотрите, куда ушёл трафик:

```bash
sudo docker stop vibedpn-wg-client-1
sudo vibedpn doctor
```

В строке `router` будет:

```
uplink vps gateway 10.77.0.10 does not answer; its traffic goes through wg-second (routing.fallback)
```

То же видно ещё в трёх местах:
- В `vibedpn status`: `uplink vps: gateway does not answer, traffic through wg-second`
- В журнале (`vibedpn events --kind uplink` и страница «Журнал»): «Трафик идёт через wg-second»
- На странице «Статус»: заголовок называет запасной выход, у карточки VPS — строка «Трафик идёт через»

Верните шлюз — через 5–10 секунд трафик снова идёт через VPS:

```bash
sudo docker start vibedpn-wg-client-1
```

## 5. Выход без подмены для аккаунтов, привязанных к стране

Смена адреса посреди сессии для Anthropic, банка или платёжной системы опаснее перерыва: аккаунт могут
заблокировать за «прыгающий» адрес. Такому трафику запасной выход не нужен.

Правило в умном режиме с флагом `sticky` на запасной выход не уходит: замолчал его выход — трафик стоит,
что бы ни говорил `failopen`, а вернулся — идёт снова через тот же адрес.

В панели: страница «Правила», в строке правила, списка или сети — переключатель «Без подмены».

То же командами:

```bash
sudo vibedpn rule add claude.ai vps --sticky
sudo vibedpn rule add anthropic.com vps --sticky
```
Действует только в `routing.mode: smart`: в `full` правил сайтов нет, и весь трафик следует цепочке.

---

## 6. Что учесть

- **Адрес выхода меняется.** Сайты видят адрес запасного выхода: сессии, привязанные к адресу, могут попросить войти снова.
- **Tor в цепочке — только TCP и DNS.** UDP через него не идёт: звонки и игры на время переключения замолчат.
- **Умерший VPS замечается не сразу.** Остановленный контейнер-шлюз ядро видит за 5 секунд.
  VPS, умерший за живым контейнером, — когда рукопожатие WireGuard станет старше 180 секунд: до трёх минут.
  Меньше нельзя: живой туннель обновляет рукопожатие примерно раз в две минуты.
- **Tor, xray и dpn судятся по контейнеру.** Для них ядро проверяет только, отвечает ли контейнер-шлюз.
  Живой контейнер с мёртвым путём за ним цепочка не заметит.
- **Запасной выход тоже проверяется.** Его шлюз ядро спрашивает так же, как основной.
  Молчание запасного выхода попадает в журнал и в тревоги Telegram-бота.
- **Закрытие частных сетей VPS держится.** `upstreams.vps.lan_access: false` стоит на метке трафика `vps`.
  Трафик `vps`, ушедший через `wg-second`, по-прежнему не достанет ни одной частной сети.
