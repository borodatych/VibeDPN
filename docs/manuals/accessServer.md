# ДОСТУП ПО ССЫЛКЕ

Как дать своим людям вход в коробку из любой сети: каждому ссылка `vless://` или QR-код.

---

## 1. Что это

Коробка поднимает свой маскирующий сервер VLESS с REALITY.
Для фильтра по дороге соединение выглядит как обычный заход на сайт-прикрытие, поэтому оно проходит там, где WireGuard режут.

**На домашней коробке** человек снаружи получает то же, что устройство дома: режим `routing.mode`, правила сайтов и сетей, выход через Tor или Mysterium по правилу, блокировку рекламы AdGuard.
**На VPS** человек выходит прямо в интернет с адреса VPS.

Сама коробка и сети вокруг неё людям закрыты: петля, где ядро отвечает без пароля, домашняя LAN, частные сети.
Сервер не ведёт журнал соединений — куда ходят люди, не хранится нигде.
Считается только объём трафика на человека: в панели и в `vibedpn access list`.

Это для семьи и друзей.
Незнакомым людям лучше раздавать с VPS: жалобы на их трафик иначе придут на ваш домашний адрес.

---

## 2. Что нужно

**Домашней коробке — три вещи:**

1. **Белый адрес дома.** Если провайдер выдаёт адрес из CGNAT, входящие до дома не доходят вовсе, и выход один — VPS.
   Проверка: `vibedpn doctor --network` показывает внешний адрес коробки; если он совпадает с адресом на внешнем порту роутера, который смотрит в провайдера, адрес белый.
   При двух роутерах подряд смотрите на внешний из них: у вашего роутера за роутером провайдера на внешнем порту всегда частный адрес.
2. **Проброс порта TCP 443 на коробку.** Если роутеров два подряд — например, свой за роутером провайдера, — проброс нужен на обоих: на роутере провайдера на ваш роутер, на вашем роутере на коробку.
   Вместо проброса на роутере провайдера можно поставить ваш роутер в его DMZ.
3. **Имя, которое следует за адресом.** Домашний адрес время от времени меняется, и ссылка с голым адресом однажды перестанет работать.
   Заведите имя в сервисе DDNS — DuckDNS, dynv6 или любом другом с адресом обновления — и скопируйте адрес обновления с токеном.

**VPS не нужно ничего:** адрес у неё постоянный, а порт в её файрволе коробка открывает сама.

---

## 3. Включить

На коробке, по порядку:

```bash
sudo vibedpn ddns set
```

Команда спросит адрес обновления, не показывая его на экране.
Адрес начинается с `https://`: в нём токен.
Если сервис хочет ваш адрес в самой ссылке, поставьте на его место `{ip}` — коробка подставит свой внешний адрес.

```bash
sudo vibedpn access enable --address myhome.duckdns.org
```

```bash
sudo vibedpn up
```

Проверка:

```bash
sudo vibedpn doctor --network
```

Нужны три строки `ok`:
- `access` — сервер работает, и роутер коробки направляет людей так же, как устройства дома;
- `access name` — имя из ссылок ведёт на эту коробку;
- `ddns` — сервис принял текущий адрес.

То же самое — на странице «Доступ» панели: включить сервер, задать имя, вставить адрес обновления DDNS.

На VPS хватает `sudo vibedpn access enable` и `sudo vibedpn up`: ссылки назовут `wg_server.endpoint`.

## 4. Люди

```bash
sudo vibedpn access add anna
```

Команда печатает ссылку и QR-код.
С ключом `--out anna.txt` ссылка ложится в файл с правами 600.
В панели — поле «Имя человека» и кнопка «Добавить и показать ссылку»: панель покажет QR-код.

Ссылку импортирует любое приложение с VLESS и REALITY:
- Android — v2rayNG или Hiddify;
- iPhone — Streisand или Hiddify.

Ссылка впускает того, у кого она есть: отдавайте её только этому человеку.

```bash
sudo vibedpn access rm anna
```

Ссылка перестаёт работать сразу; соединения остальных не рвутся.
Показать ссылку снова — `sudo vibedpn access link anna` или «Показать ссылку» в панели.
Кто сколько скачал — `vibedpn access list`, с ключом `--since 2026-09-01` за период.

---

## 5. Сайт-прикрытие

REALITY одалживает рукопожатие TLS 1.3 у настоящего сайта; по умолчанию это `dl.google.com`.
Годится не любой сайт: с `www.microsoft.com`, например, рукопожатие не проходит никогда, хотя встроенная проверка Xray называет его подходящим.
Поэтому проверка здоровья контейнера — настоящее соединение сервера к самому себе через прикрытие: неподходящий сайт виден в `vibedpn doctor` как `unhealthy: access`, раньше, чем у людей.

Сменить:

```bash
sudo vibedpn access enable --target www.apple.com
```

```bash
sudo vibedpn up
```

Выданные ссылки при смене прикрытия нужно раздать заново: сайт записан в каждой.

---

## 6. Если человек не подключается

Почти всё коробка видит сама — `sudo vibedpn doctor --network`:
- `unhealthy: access` — сервер не может одолжить рукопожатие у сайта-прикрытия: проверка здоровья и есть такое соединение. Смените сайт, как в разделе 5.
- `access` — fail: роутер коробки не направляет сервер, люди шли бы мимо его правил. Поможет `sudo vibedpn restart`.
- `access name` — warn или fail: имя из ссылок не ведёт на коробку. Причину покажут строка `ddns` и `sudo vibedpn ddns show` — ответ сервиса на последний вызов.

Если `doctor` чист, а человек не входит:
- **Проверяйте с мобильного интернета, а не с домашнего Wi-Fi.** Изнутри дома соединение к внешнему адресу должен развернуть обратно роутер (NAT loopback), и умеют это не все — при двух роутерах подряд тем более.
- **Проброс порта.** TCP 443 должен вести на коробку через все роутеры по дороге; без проброса соединение снаружи висит до таймаута.
- **Ссылка устарела.** После смены имени или сайта-прикрытия выданные ссылки ведут по-старому — раздайте новые.

---

## 7. Ограничения

- **Имя в ссылках, а не адрес.** Ссылка с голым адресом умрёт при первой смене адреса дома.
- **Режим `full` через Tor замедляет каждое новое соединение.** Сервер на каждое соединение обращается к сайту-прикрытию, и в режиме `full` это обращение тоже идёт через аплинк. Для коробки-сервера удобнее режим `smart`.
- **Сменили `address`** — после `vibedpn up` новые ссылки называют новый адрес, а выданные раньше — старый: раздайте их заново.

**Не проверено:**
- пропускают ли мобильные операторы такое соединение к домашнему адресу — это видно только с телефона снаружи;
- не замечает ли фильтр, что сайт-прикрытие отвечает с домашнего адреса; если соединения начнут рваться, смените прикрытие.
