# ВЫХОД ЧЕРЕЗ МАСКИРУЮЩИЙ ТРАНСПОРТ (АПЛИНК `xray`)

Как пустить трафик коробки через сервер, который прикидывается обычным сайтом
Это нужно там, где обычный WireGuard не проходит

Нужна ссылка вида `vless://…` — её даёт ваш провайдер такого доступа или ваш собственный сервер
Ссылка содержит учётные данные: обращайтесь с ней как с паролем

---

## 1. Что это даёт

Провайдер, который роняет рукопожатие WireGuard, маскирующий транспорт обычно пропускает
Снаружи это похоже на обычное TLS-соединение с обычным сайтом
В отличие от [Tor](torUplink.md) скорость здесь ограничена только вашим сервером, а не сетью добровольцев

Ограничения первого выпуска:

- Переносится только TCP (как у Tor); DNS идёт прежним путём
- Принимаются транспорты `tcp`, `ws`, `grpc` и защита `none`, `tls`, `reality`
- Ссылки `ss://` (Shadowsocks) пока не принимаются

Всё, что не принято, коробка отвергает **с объяснением**, а не молча

---

## 2. Положить ссылку и включить выход

**Шаг 1.** В панели коробки откройте страницу «Выходы», карточку «Маскирующий выход по ссылке»
Вставьте ссылку в поле «Ссылка (vless://…)» и нажмите «Сохранить ссылку»
Коробка покажет «Ссылка сохранена; коробка показывает сервер, но не саму ссылку.»
Сама ссылка обратно не отдаётся никогда

**Шаг 2.** Нажмите «Включить» в той же карточке
Коробка сама поднимет шлюз и покажет строку «Сервер: …, транспорт …» — адрес сервера и вид транспорта

**Проверка:** у карточки отметка «включён», строка «Сервер» называет ваш сервер, а не что-то другое

**То же командами.** Ссылка не передаётся аргументом команды:
Аргументы видны в `ps` любому пользователю коробки и остаются в истории оболочки
Поэтому либо ввод по запросу, либо файл

```bash
sudo vibedpn xray enable
```

Команда спросит ссылку и покажет, что поняла: адрес сервера и вид транспорта
Если ссылка лежит в файле:

```bash
sudo vibedpn xray enable --link-file /tmp/link.txt
shred -u /tmp/link.txt
```

Ссылка ляжет в `secrets/xray-link` с правами только для владельца
В `config.yaml` останется только `upstreams.xray.enabled: true`

Затем поднять шлюз и посмотреть, что коробка поняла:

```bash
sudo vibedpn up
sudo vibedpn xray show
```

`show` печатает адрес сервера и вид транспорта — и ни слова из учётных данных

## 3. Направить трафик

**Шаг 1.** Весь трафик LAN — на странице «Статус», карточка «Маршрутизация»
В строке «Аплинк» нажмите «XRAY», затем в строке «Режим» — «Полный — через аплинк» и подтвердите

**Проверка:** заголовок «Статуса» говорит «LAN выходит через xray»

**То же командами.**

```bash
sudo vibedpn upstream xray
sudo vibedpn mode full
```

**Шаг 2.** Только отдельные сайты в умном режиме — в панели этого пока нет
Умного режима в карточке «Маршрутизация» нет, а на странице «Правила» в выборе канала нет xray
Поэтому командами:

```bash
sudo vibedpn mode smart
sudo vibedpn rule add rutracker.org xray
```

**Шаг 3.** Отдельное устройство — тоже только командой
На странице «Устройства» политики через xray нет

```bash
sudo vibedpn device set 192.168.50.23 xray
```

---

## 4. Проверить

**Шаг 1.** На странице «Статус» у выхода `XRAY` шлюз «отвечает»

**Шаг 2.** На той же странице, в карточке «Проверка коробки», нажмите «Проверить с адресами выходов» и подтвердите
Строка `exit xray` должна показать адрес вашего сервера, а не адрес коробки

**То же командами.**

```bash
sudo vibedpn doctor --network
```

Если сервер недоступен, трафик **не пойдёт мимо** — шлюз его отбрасывает, это и есть kill-switch

---

## 5. Выключить

**Шаг 1.** На странице «Выходы», в карточке «Маскирующий выход по ссылке», нажмите «Выключить» и подтвердите
Сайты и устройства, отправленные через xray, сначала переведите на другой канал

**То же командами.**

```bash
sudo vibedpn xray disable
sudo vibedpn up
```

Шлюз остановится
Ссылка останется в `secrets/xray-link`: удалите файл сами, если она больше не нужна
В панели удалить её нельзя

---

## 6. Если не работает

Сначала в панели:

- Страница «Статус»: что карточка выхода `XRAY` говорит про шлюз и kill-switch
- Страница «Выходы», карточка «Журналы»: выберите `xray` и нажмите «Показать» — что сказал сам xray при чтении конфигурации
- Ссылки доступа и ключи в журнале скрыты (`***`), так что строки можно пересылать
- Страница «Статус», карточка «Проверка коробки», «Проверить с адресами выходов»: адрес коробки вместо адреса сервера → трафик идёт мимо туннеля

То же командами:

- `vibedpn logs xray` — что сказал сам xray при чтении конфигурации
- `vibedpn xray show` — коробка поняла ссылку так, как вы ожидали?
- `doctor --network` показывает адрес коробки вместо адреса сервера → трафик идёт мимо туннеля

Сервер за границей может резать по стране: проверьте ссылку в обычном клиенте на телефоне
