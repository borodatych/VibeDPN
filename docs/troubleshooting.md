# Что делать, когда не работает

Здесь симптомы, с которыми реально сталкивались на живых коробках, и что по каждому проверять.
Каждый пункт устроен одинаково: что видно → чем проверить → что это значит → что сделать.

Мануалы по настройке живут в [manuals/](manuals/), разборы и факты — в [knowledge/](knowledge/).

---

## Первым делом

```bash
sudo vibedpn doctor
```

Доктор проверяет хост и коробку и по каждой строке говорит, что именно не так и какую команду
выполнить. Он ничего не чинит молча.

```bash
sudo vibedpn doctor --network
```

То же плюс то, чего не видно без выхода в сеть: внешний адрес самой коробки и адрес выхода через
каждый включённый аплинк. Занимает десятки секунд: Tor медленнее туннеля по устройству.

Доктор говорит `warn` там, где не смог проверить, и `fail` только про проверенное.
`ok` он не ставит по предположению — это осознанное правило, а не случайность.

## Устройства LAN не выходят в интернет

**Проверить:**

```bash
sudo vibedpn doctor --network
sudo vibedpn status
```

**Что искать в ответе:**

- `[FAIL] exit <аплинк>` — трафик уходит не через туннель; смотрите `vibedpn logs <сервис>`
- шлюз аплинка не отвечает — в журнале ядра будет строка про него
- `routing.mode` не тот, которого вы ждёте

**Частая причина, стоившая нам вечера:** у устройства осталась **политика с прошлых проверок**.
Политика устройства сильнее режима: устройство с `bypass` ходит напрямую даже в режиме `full`, а
устройство с `blocked` не ходит никуда.

```bash
sudo vibedpn device list
sudo vibedpn device unset <адрес или mac>
```

**Если выхода нет вообще ни у кого** — это может быть kill-switch, и он так и задуман:
при `failopen: false` остановленный шлюз отрезает LAN, а не выпускает её напрямую.

```bash
sudo vibedpn status        # шлюз аплинка отвечает?
sudo vibedpn logs <сервис> # почему контейнер шлюза не поднялся
```

## Telegram не работает, а сайты открываются

Telegram ходит **по адресам**, а не по именам, поэтому доменные правила его не ловят.

В панели это кнопка «Добавить сети Telegram» в разделе сетей.
Из терминала сети заводятся по одной — готовый список и источник в
[manuals/torUplink.md](manuals/torUplink.md):

```bash
sudo vibedpn net add 149.154.160.0/20 tor
sudo vibedpn net list
```

Проверьте заодно политику самого телефона (`vibedpn device list`): именно она однажды и держала
Telegram мимо туннеля, а выглядело это как «Tor не работает».

## `doctor` пишет `exit dpn — no session`

Это **не утечка**, а состояние: у consumer нет сессии в сети Mysterium.

Собственный трафик ноды обязан идти напрямую — ей нужны discovery, блокчейн и endpoint выходной
ноды. Трафик LAN при этом наружу не выпускается вовсе: его держит kill-switch шлюза.

Чтобы сессия появилась, identity ноды должна быть зарегистрирована (это транзакция в сети и стоит
денег — коробка её сама не начинает). Подробности — [knowledge/myst/exitCheck.md](knowledge/myst/exitCheck.md).

## Нода Mysterium не видит ни одного предложения

Симптом: карточка выхода Mysterium в панели пуста, выбрать страну не из чего, сессия не поднимается.

**Что это:** провайдер душит ответы сервисов Mysterium по объёму. Мелкие ответы проходят, а список
предложений весит около 8 МБ и не доезжает никогда.

**Что делать:** включить аплинк `tor` — ретранслятор сам уведёт туда имена, которые провайдер
фильтрует.

```bash
sudo vibedpn tor enable
sudo vibedpn up
sudo vibedpn logs myst-relay   # ждём строку "it goes through Tor"
```

Замеры и разбор — [knowledge/myst/relayThrottling.md](knowledge/myst/relayThrottling.md).

## Tor долго поднимается или не поднимается

Snowflake-мост бутстрапится минутами, а не секундами — это норма при первом старте.

```bash
sudo vibedpn logs tor
sudo vibedpn tor show
```

Если мосты не отвечают совсем, замените список мостов своими:
[manuals/torUplink.md](manuals/torUplink.md).

Через Tor ходит только TCP. `ping` через этот аплинк молчит **по устройству**, а не из-за поломки —
не делайте по нему выводов.

## `vibedpn update` упал

**`install.sh failed; the box keeps running the previous version`** — обновление не состоялось, и
коробка осталась на прежней версии; это штатное поведение, а не поломка.

Самая частая причина — недоступный github в момент запуска:

```bash
sudo git -C /opt/vibedpn fetch origin   # проверить руками
```

Повторите `sudo vibedpn update` позже.

**Правка `install.sh` доезжает со следующего прогона:** скрипт обновляет собственный файл, а
работает всё ещё со старого. Это не ошибка, просто запустите его второй раз.

## Панель не открывается или забыт пароль

```bash
sudo vibedpn status          # ui запущен?
sudo vibedpn logs ui
sudo vibedpn password        # задать пароль заново, спросит дважды без эха
```

Панель слушает только адрес коробки в LAN — снаружи её нет по замыслу.

---

## Wi-Fi коробки не появляется

```bash
sudo vibedpn wifi show
sudo vibedpn logs hostapd
sudo vibedpn events          # клиенты приходят и уходят
```

В журнале hostapd ошибка конфига и ошибка драйвера различимы: неверный ключ он ловит при разборе
файла, а живой конфиг на недоступном радио падает уже на драйвере (`Failed to initialize driver
'nl80211'`, затем `AP-DISABLED`). Разбор — [knowledge/linux/hostapdConfigCheck.md](knowledge/linux/hostapdConfigCheck.md).

## Не пускает по ssh с моего адреса

Коробка защищена fail2ban: пять неудачных попыток за 10 минут — час бана на **весь адрес**,
включая вход по ключу.

С самой коробки (с консоли или с другого адреса):

```bash
sudo fail2ban-client status sshd
sudo fail2ban-client set sshd unbanip <адрес>
```

Проверить, что бан вообще действует, можно только следствием, а не статусом службы —
[knowledge/security/fail2ban.md](knowledge/security/fail2ban.md).

## В режиме `full` не открываются IPv6-сайты, AAAA пустые

Так и задумано: аплинки IPv4, и коробка не выдаёт себя за IPv6-роутер. AdGuard отвечает на AAAA
пусто, чтобы устройства не уходили мимо туннеля.

`doctor` предупреждает об этом отдельной строкой, если у устройств есть глобальный IPv6 от роутера
провайдера — тогда часть трафика пойдёт мимо коробки.

## Что-то сломалось после правок — вернуть как было

```bash
sudo vibedpn backup                       # сначала копия текущего состояния
sudo vibedpn restore /путь/к/архиву.tar.gz
sudo vibedpn up
```

`restore` ничего не удаляет: текущие файлы уезжают в `restore-backup-<время>`.
Копию стоит держать **вне коробки** — `scripts/pullBackup.sh`, см.
[manuals/installation.md](manuals/installation.md).

---

## Если ничего не помогло

Соберите факты одной командой и приложите их к вопросу:

```bash
sudo vibedpn doctor --json > /tmp/doctor.json
sudo vibedpn status
sudo vibedpn logs --tail 200 core
```

В журналах коробки нет паролей и ключей: секреты в них не выводятся.
