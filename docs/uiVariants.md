# ДВА ВАРИАНТА UI НА START0: N100 И RASPBERRY PI

Решение по первому пункту Stage 6.
UI — приложение на старт-паке start0 (Point0 + Prisma + better-auth + Bun), решение владельца 2026-09-12.
Кодовая база одна, варианта два: `full` для N100 и `lite` для Raspberry Pi.

---

## 1. Что показал замер

Стенд: Docker на VM colima, aarch64, 2 CPU, 2 ГиБ, пак start0 v0.1.23 без правок, 2026-09-13.

| Что | Значение |
|---|---|
| Сборка `bun run build` в Docker на VM 2 ГиБ | падает через 988 с: *cannot allocate memory* |
| Та же сборка нативно (Bun 1.3.14, macOS) | 79 с, пик RSS 2.18 ГиБ, `dist` 87 МБ |
| Runtime-образ arm64 (`oven/bun:1`, prod-зависимости, `dist`) | 469 МБ |
| Старт сервера после миграций | 290 мс, здоров через ~5 с после `up` |
| RSS приложения в простое | 205 МиБ |
| RSS приложения после 600 запросов (`/` и `/api/health`) | 283 МиБ |
| RSS `postgres:17-alpine` | 69–78 МиБ |
| CPU в простое | меньше 1.5 % одного ядра |

**Вывод из замера:**
Сборка UI на коробке невозможна ни на Pi, ни на N100 с 2 ГиБ.
Работающий UI с базой стоит около 360 МиБ.

**Замер вариантов (2026-09-13, та же VM, образы из нативного `dist`, `oven/bun:1.4.2`, `postgres:17.11-alpine`):**

| Что | `full` | `lite` |
|---|---|---|
| RSS панели в простое (через 30 с после старта) | 181 МиБ | 172 МиБ |
| RSS панели после 600 запросов (`/sign-in` и `/api/health`) | 266 МиБ | 259 МиБ |
| RSS `ui-db` | 69 МиБ | 51 МиБ |
| Вместе после нагрузки | 335 МиБ | 310 МиБ |
| Соединений с базой (`pg_stat_activity`) | 5 | 1 |
| Образ | 467 МБ | 466 МБ |

**Вывод:** `lite` экономит 25 МиБ — это воркер, backplane и маленький `shared_buffers`.
Порог 300 МиБ на VM превышен на 10 МиБ. Основную память занимает сам Bun с приложением, а не вырезанные части.
Решение о пороге и минимуме памяти — после приёмки на N100.

## 2. Что режется для Pi

**Не режется:**
- **Postgres.** Пак привязан к нему адаптером Prisma (`@prisma/adapter-pg`), очередью `pg-boss` и backplane сокетов на LISTEN/NOTIFY. Переход на SQLite — это форк схемы и адаптеров ради ~70 МиБ.
- **better-auth.** Вход в UI обязателен в обоих вариантах. Пароль — тот же, что у `/api/`.
- **Bun.** Падение с *Illegal instruction* на ARMv8.0 (Cortex-A72 у Pi 4) исправлено в Bun v1.3.9. Пак требует `bun ^1.3.14`.

**Режется в `lite` — константой сборки `UI_VARIANT=lite`, без форка:**
- **Воркер `pg-boss`.** Им пользуется только heartbeat `modules/health/worker.ts`. В `lite` он не стартует и не попадает в бандл: исходников воркера в серверных source map нет (проверено сборкой обоих вариантов).
- **Backplane сокетов на Postgres** (`lib/backplane.ts`: свой пул и LISTEN). В одном процессе сокеты работают в памяти, backplane нужен только нескольким процессам (документация Point0). В бандле `lite` его нет.
- **Тяжёлые экраны:** графики истории, статистика ноды, живые подписки. Их ещё нет; правило для них записано в `ui/src/engine.ts`: ветвление по `process.env.UI_VARIANT` прямо в месте использования, в `lite` — опрос query по таймеру.
- **Настройки Postgres для Pi:** `shared_buffers=32MB`, `max_connections=20` (в `full` — умолчания Postgres, 128MB и 100).

**Грабля константы:** компилятор Point0 подставляет только само выражение `process.env.UI_VARIANT`. Булево значение, экспортированное из другого модуля, для бандлера переменная: ветка с её динамическим импортом уезжала в `lite` отдельным chunk на 360 КиБ.

**Порог приёмки `lite`:**
- RSS приложения и Postgres вместе — не больше 300 МиБ под нагрузкой панели.

**Решением владельца 2026-09-13 приёмка — на N100, Raspberry Pi нет:**
- оба варианта принимаются на N100 (amd64);
- `lite` там же — с памятью контейнеров `ui` и `ui-db`, ограниченной как у Pi с 2 ГБ;
- поведение на Cortex-A72 (ARMv8.0) не проверено: это открытый риск, а не условие приёмки. Падение Bun на ARMv8.0 закрыто в v1.3.9 только по отчёту апстрима.

Порог не выдержан — минимум памяти для роли с UI в варианте `lite` поднимается до 4 ГБ, это записывается в `docs/roles.md`.

## 3. Сборка в CI

- **Коробка UI не собирает.** Образы приходят готовыми из GHCR.
- **Задача `ui-image`:** `docker buildx` на `linux/amd64,linux/arm64` с `--build-arg UI_VARIANT=full|lite`.
- **Сборка `dist` один раз на вариант, на amd64-раннере.** `dist` не зависит от архитектуры, arm64-стадия только ставит prod-зависимости. Так сборка не упирается в память QEMU.
- **Теги:** `ghcr.io/borodatych/vibedpn-ui:<тег>-full` и `…-lite` (задача `images`, суффикс через `flavor` metadata-action). Тег без суффикса больше не обновляется: `compose.yaml` всегда дописывает вариант, по умолчанию `-full`.
- **Смоук каждого образа** (`ui-image`, matrix `full`/`lite`): миграции, `/api/health`, вход паролем и по имени коробки, ядро за сессией, лимит входа, отказ старта без секретов.
- **Смоук arm64-образа под QEMU.** Сборка Bun с исправлением ARMv8.0 сама проверяется в QEMU с базовым CPU. Отдельная приёмка на Pi 4 всё равно обязательна: эмуляция не доказывает поведение Cortex-A72.

## 4. Выбор варианта в `compose.yaml`

- **Ключ `ui.variant`** (`full` | `lite`) в `config.yaml` → `VIBEDPN_UI_VARIANT` в `.env`, по умолчанию `full`.
- **Образ сервиса `ui`:** `ghcr.io/borodatych/vibedpn-ui:${VIBEDPN_TAG}-${VIBEDPN_UI_VARIANT}`.
- **Postgres UI** — сервис `ui-db` того же профиля, данные в `data/ui-db`, пароль генерирует `init` в `secrets/`; у `lite` `.env` получает `VIBEDPN_UI_DB_SHARED_BUFFERS=32MB` и `VIBEDPN_UI_DB_MAX_CONNECTIONS=20`.
- **`vibedpn init`** ставит `lite`, если `MemTotal` хоста меньше 4 ГиБ, и `full`, если больше или память не прочиталась; `--ui-variant full|lite` выбирает явно (Pi 5 с 8 ГБ спокойно берёт `full`).
- **`doctor`** — проверка `ui variant`: WARN, когда `full` стоит на хосте с памятью меньше 4 ГиБ.

## 5. Порядок пунктов Stage 6

1. Каркас `full` из пака: экран входа, слушает только LAN, сервис `ui` и Postgres в `compose.yaml`, задача CI `ui-image`.
2. Константа `UI_VARIANT=lite` — сделано 2026-09-13; приёмка — на N100 с ограничением памяти как у Pi (решение владельца: Raspberry Pi нет).
3. Экраны статуса, устройств и ноды — в обоих вариантах с первого коммита.
